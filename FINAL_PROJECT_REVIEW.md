## 2. Критические проблемы

### CRIT-001: Несоответствие demo RUL checkpoint

**Где найдено:**  
`models/demo_best/README.md`, `src/prediction/demo_inference.py`, git status.

**Почему критично:**  
README и default path ожидают `models/demo_best/rul/xjtu_rul.pth`, но текущий git status показывает удаление этого файла. При этом другие RUL-модели в `models/demo_best/rul/` есть. На защите это может сломать “полупродовый” сценарий или вызвать fallback на старую модель.

**Как исправить:**  
Выбрать лучший checkpoint из `models/demo_best/rul/*.pth` и закрепить его как `xjtu_rul.pth` либо изменить default path и README.

**Сколько шагов:** 4

**Как проверить:**  
`discover_rul_models("demo")` показывает выбранную demo-модель, `make demo` запускает RUL-сценарий без fallback.

### CRIT-002: В дипломе заявлена функциональность, которой нет в UI

**Где найдено:**  
Дипломный раздел 3.6; `app.py`; `src/prediction/demo_inference.py`.

**Почему критично:**  
Комиссия может сравнить текст с демонстрацией. В тексте описаны загрузка файла, SHAP, ensemble confidence interval и `InferenceService`. В коде фактически selectbox по тестовым сигналам, gradient attribution, одиночная RUL-модель и набор функций без `InferenceService`.

**Как исправить:**  
Либо реализовать функции, либо переписать раздел 3.6 под фактический код.

**Сколько шагов:** 3-8, зависит от выбранного варианта.

**Как проверить:**  
Каждое утверждение раздела 3.6 имеет соответствующий кодовый элемент.

## 3. Важные проблемы

1. **CWRU split по окнам, а не по файлам.**  
   `src/classification/train.py` делит окна 70/15/15, но `src/classification/data_loader.py` нарезает много окон из одного `.mat`. Нужно grouped split или честное ограничение.

2. **RUL в километрах не калиброван.**  
   `src/utils/health_index.py` использует `L_MAX_KM = 1_000_000`; это демонстрационная шкала, а не подтвержденный расчет ресурса вагона.

3. **Скоростные пороги эвристические.**  
   `src/utils/thresholds.py` задает 0.7/1.0/1.3 коэффициенты. Нужна ссылка/обоснование или пометка “демонстрационное правило”.

4. **Нет data passport.**  
   Методичка требует паспорт данных; сейчас описание размазано по README и коду.

5. **Нет `.env.example`.**  
   Переменные окружения есть, но не собраны в файл-пример.

6. **Нет CI/CD.**  
   `.github/workflows` не найден. Для методички достаточно минимального CI с pytest.

7. **Нет видео demo 2-4 минуты.**  
   Среди проверенных материалов не найдено. Возможно лежит вне репозитория, но для пакета защиты нужно подготовить.

8. **Нет evidence публикации/регистрации программы/внешней рецензии в репозитории.**  
   Методичка это требует или рекомендует для магистерской защиты. Если материалы есть вне репозитория, их нужно собрать отдельно.
