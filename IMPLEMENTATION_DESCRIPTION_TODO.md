## 2. Архитектура проекта

### Основные слои системы

1. **Data layer:** `data/raw/CWRU`, `data/raw/XJTU-SY`, loaders в `src/classification/data_loader.py`, `src/prediction/data_loader.py`.
2. **Signal preprocessing layer:** STFT для CWRU, CWT для XJTU-SY, статистические признаки, kurtogram.
3. **ML layer:** CNN-классификаторы, CNN+temporal RUL-модели, HMM baseline.
4. **Inference layer:** `src/prediction/demo_inference.py`.
5. **Post-processing layer:** HI, статусы, RUL в км, скоростные пороги.
6. **Presentation layer:** Streamlit `app.py`, Plotly-графики.
7. **Experiment layer:** train scripts, MLflow, Optuna, reports.

### Поток данных

Для классификации:

```text
CWRU .mat -> DE_time signal -> windows 1024 -> STFT -> CNN classifier -> class + confidence -> attribution heatmap -> Streamlit
```

Для RUL:

```text
XJTU-SY CSV sequence -> two vibration channels -> CWT scalograms -> CNN encoder -> temporal block -> normalized RUL -> HI/status/km -> Streamlit/CLI
```

### Архитектура программной системы

В программной части работы реализован модульный исследовательский прототип системы предиктивной вибродиагностики буксового узла. Архитектура построена по слоистому принципу и включает подсистему загрузки данных, подсистему предобработки вибросигналов, подсистему машинного обучения, слой инференса, слой диагностической постобработки и пользовательский веб-интерфейс.

На вход классификационной ветви поступают стендовые вибросигналы набора CWRU в формате `.mat`. Из исходных файлов извлекается канал виброускорения приводной стороны подшипника, сигнал нарезается на окна фиксированной длины, после чего для каждого окна строится спектрограмма кратковременного преобразования Фурье. Полученное частотно-временное представление передается в сверточную нейронную сеть, адаптированную под одноканальный вход и десять диагностических классов.

Прогностическая ветвь использует run-to-failure данные XJTU-SY. Для каждого подшипника хронологическая последовательность CSV-файлов преобразуется в последовательность двухканальных CWT-скалограмм. Пространственные признаки из каждой скалограммы извлекаются CNN-энкодером, после чего последовательность признаков обрабатывается временным блоком LSTM, GRU, TCN или Transformer. Выходом модели является нормированный остаточный ресурс в диапазоне от 1 до 0.

Слой постобработки преобразует прогноз RUL в сглаженный Health Index, диагностический статус и демонстрационную оценку остаточного пробега. Пользовательское взаимодействие реализовано через Streamlit-интерфейс, который позволяет выбрать модель, тестовый сигнал или подшипник, выполнить инференс и визуализировать результат в виде графиков вибросигнала, прогноза RUL, Health Index и статуса состояния.

## 3. Описание ключевых модулей

**Назначение:**  
Загрузка CWRU и построение STFT-спектрограмм.

**Основная логика:**

**Входные данные:**

**Выходные данные:**

### Модуль: `src/classification/model.py`

**Назначение:**  
Фабрика CNN-моделей для классификации спектрограмм.

**Основная логика:**  
`get_model()` создает torchvision backbone, адаптирует первый сверточный слой под `in_channels=1`, заменяет classifier head под `num_classes=10`, оборачивает в `SpectrogramAdapter`.

**Входные данные:**  
Тензор `[batch, 1, freq, time]`.

**Выходные данные:**  
Логиты `[batch, 10]`.

**Связанные компоненты:**

### Модуль: `src/prediction/data_loader.py`

**Назначение:**  
Формирование RUL-последовательностей из XJTU-SY.

**Основная логика:**  
CSV сортируются по номеру, из каждого файла берутся horizontal и vertical channels, строится CWT с Mexican hat wavelet, несколько последовательных файлов объединяются в sequence. Target RUL вычисляется линейно по позиции в жизненном цикле.

**Входные данные:**  
`data/raw/XJTU-SY/<режим>/<Bearing>/NN.csv`.

**Выходные данные:**  
`x`: `[seq_length, 2, cwt_scales, window_size]`, `y`: `[1]`.

**Связанные компоненты:**  
`src/prediction/model.py`, train scripts, `demo_inference.py`.

**Что написать в дипломе:**

### Модуль: `src/prediction/model.py`

**Назначение:**  
Гибридные модели RUL.

**Основная логика:**  
`create_cnn_encoder()` строит CNN encoder. `UniversalHybridRULNet` применяет encoder к каждому временному окну, добавляет speed-признак, затем temporal block и linear head. `TemporalOnlyRULNet` работает по кэшированным CNN-признакам.

**Входные данные:**  
Скалограммы `[batch, seq_len, channels, height, width]`, optional speed.

**Выходные данные:**  
Нормированный RUL `[batch, 1]`.

**Связанные компоненты:**  
`src/prediction/train*.py`, `demo_inference.py`.

## 8. Готовые черновики текста

### Описание проекта

В рамках работы разработан исследовательский программный прототип модуля предиктивной вибродиагностики буксового узла, объединяющий классификацию дефектов подшипника и прогнозирование остаточного ресурса по вибросигналам. Программная реализация основана на открытых наборах данных CWRU и XJTU-SY, которые используются как модельная экспериментальная база для отработки алгоритмов частотно-временной обработки сигналов и нейросетевого анализа деградации. Полученный прототип демонстрирует ключевую функциональность интеллектуального диагностического модуля: обработку вибросигнала, инференс обученной модели, расчет диагностического статуса и визуализацию результата.

### Описание архитектуры

Архитектура программного решения построена в виде набора независимых модулей. Нижний уровень отвечает за чтение исходных данных и формирование обучающих представлений: для CWRU применяется кратковременное преобразование Фурье, а для XJTU-SY - непрерывное вейвлет-преобразование. Следующий уровень содержит модели машинного обучения: сверточные классификаторы для определения типа дефекта и гибридные CNN-temporal модели для прогнозирования остаточного ресурса. Поверх моделей расположен inference-слой, который загружает checkpoint, выполняет предобработку, запускает PyTorch-модель и возвращает результат в унифицированном виде. На верхнем уровне находится Streamlit-интерфейс, визуализирующий сигнал, прогноз RUL, Health Index и диагностический статус.

### Описание реализации

Классификационная ветвь реализована в каталоге `src/classification`. Исходный вибросигнал CWRU считывается из `.mat` файлов, разбивается на окна фиксированной длины и преобразуется в STFT-спектрограммы. Для классификации используется фабрика моделей, поддерживающая несколько архитектур torchvision, включая ResNet-18. Прогностическая ветвь реализована в каталоге `src/prediction`: данные XJTU-SY преобразуются в последовательности двухканальных CWT-скалограмм, после чего обрабатываются гибридной моделью, состоящей из CNN-энкодера и временного блока LSTM, GRU, TCN или Transformer.

### Описание ключевых модулей

Ключевым модулем демонстрационного контура является `src/prediction/demo_inference.py`. Он выполняет поиск доступных checkpoint, восстановление архитектуры модели по metadata, загрузку весов, подготовку входных данных и запуск инференса. Такой подход позволяет отделить пользовательский интерфейс от логики машинного обучения: `app.py` отвечает за отображение элементов Streamlit, а `demo_inference.py` - за вычислительную часть.

### Описание тестирования

Для проверки работоспособности проекта используется набор автоматизированных тестов на pytest. Тесты охватывают создание и прямой проход моделей, работу загрузчиков данных на малых примерах, расчет Health Index и скоростных порогов, построение визуализаций и формирование материалов для ВКР. Контрольная команда `uv run pytest --cov=src --cov=console_diagnostics --cov-report=term-missing -q` на момент проверки завершилась успешно: выполнено 26 тестов, все тесты пройдены, совокупное покрытие составило 45%. Данный показатель отражает наличие непокрытых исследовательских и CLI-модулей и должен быть повышен перед финальной сдачей тестового отчета.

### Описание результата

Результатом программной реализации является воспроизводимый демонстрационный стенд, который позволяет запустить веб-интерфейс, выбрать сохраненную модель, выполнить классификацию дефекта подшипника или прогноз остаточного ресурса и получить диагностический статус. Проект также содержит обучающие сценарии, экспериментальные checkpoint, базовые статистические и HMM-подходы, средства визуализации и Docker-конфигурацию. Система в текущем виде является исследовательским прототипом и требует дополнительной промышленной валидации на трехосевых данных колесных пар перед внедрением в реальный бортовой контур мониторинга.
