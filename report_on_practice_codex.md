# Отчет по практике: развитие гибридных моделей RUL v3_rnn, v4_tcn, v5_odd

## 1. Что было исходной задачей

Изначально были подготовлены три задания-промпта:

- `PROMPT_agent_v3_rnn (1).md` - создать `src/prediction/train_rul_hybrid_v3_rnn.py` на основе `train_rul_hybrid_v3.py` и добавить улучшенные RNN/Transformer-головы.
- `PROMPT_agent_v4_tcn.md` - создать `src/prediction/train_rul_hybrid_v4_tcn.py` и добавить семейство Temporal Convolutional Network.
- `PROMPT_agent_v5_odd.md` - создать `src/prediction/train_rul_hybrid_v5_odd.py` и добавить современные SOTA-головы: PatchTST, Conformer, Mamba.

Базовая идея всех трех задач была одинаковой: не ломать существующий пайплайн `v3`, а расширить его отдельными экспериментальными ветками, чтобы можно было честно сравнивать разные классы temporal-моделей для прогнозирования остаточного ресурса подшипников XJTU-SY.

По факту было сделано больше, чем требовали исходные промпты. Помимо самих архитектур, была доработана инфраструктура обучения, кэширования, подбора гиперпараметров, финального сравнения frozen/finetune-режимов, автоматического запуска серий экспериментов и сохранения артефактов.

## 2. Главное отличие от прошлой версии

Прошлая версия была ближе к одному учебному пайплайну: CNN-энкодер извлекал признаки из CWT-скалограмм, после чего временная модель обучалась предсказывать RUL. Новая версия превратила это в полноценную исследовательскую платформу с несколькими семействами моделей и воспроизводимыми экспериментами.

Ключевые изменения:

- Вместо одной группы temporal-моделей появились три независимых направления: `v3_rnn`, `v4_tcn`, `v5_odd`.
- Для каждого направления создан отдельный скрипт обучения, отдельное имя MLflow-эксперимента, отдельная папка графиков и отдельная папка чекпоинтов.
- Добавлены новые архитектуры, которые покрывают разные подходы к моделированию деградации: рекуррентные сети, attention-механизмы, TCN, multi-scale convolution, PatchTST, Conformer и Mamba.
- Реализован двухфазный режим обучения: быстрый HPO на замороженном CNN через feature-cache, затем финальное обучение в режиме `frozen` и/или `finetune`.
- Добавлено предобучение CNN именно под задачу RUL, а не только под классификацию дефектов.
- Добавлены дисковые кэши CWT-скалограмм и CNN-фичей, чтобы длинные эксперименты не пересчитывали одни и те же признаки.
- Добавлены Optuna, MLflow, сводные CSV, графики качества, графики Optuna, сглаженные RUL-кривые, residual plots и замер скорости инференса.
- Добавлены shell-скрипты для воспроизводимого запуска дневных и ночных серий экспериментов.

## 3. Общие улучшения пайплайна

### 3.1. Разделение экспериментов по версиям

Для каждой новой ветки заведены отдельные настройки:

- `v3_rnn`: `MLFLOW_EXPERIMENT = "XJTU_SY_RUL_HybridV3_RNN"`, чекпоинты в `models/preds_3_rnn`, графики в `reports/figures/summary/train_rul_hybrid_v3_rnn`.
- `v4_tcn`: `MLFLOW_EXPERIMENT = "XJTU_SY_RUL_HybridV4_TCN"`, чекпоинты в `models/preds_4_tcn`, графики в `reports/figures/summary/train_rul_hybrid_v4_tcn`.
- `v5_odd`: `MLFLOW_EXPERIMENT = "XJTU_SY_RUL_HybridV5_SOTA"`, чекпоинты в `models/preds_5_odd`, графики в `reports/figures/summary/train_rul_hybrid_v5_odd`.

Это важно для отчета, потому что результаты разных семейств моделей теперь не смешиваются. Можно отдельно анализировать RNN-подход, TCN-подход и SOTA-подход.

### 3.2. Более строгая организация датасета

В новых скриптах используется расширенный датасет последовательностей. Он:

- объединяет несколько bearing-директорий из XJTU-SY;
- строит последовательности через sliding window;
- поддерживает `seq_stride`, чтобы регулировать плотность выборки;
- использует отдельные bearing suffixes для train/val/test;
- строит RUL-таргет с `rul_clip=0.8`.

`rul_clip=0.8` делает таргет piecewise-like: начальная здоровая фаза не заставляет модель угадывать микроскопические отличия там, где физической деградации еще почти нет. Это уменьшает риск переобучения под конкретный подшипник.

### 3.3. Кэш CWT-скалограмм и CNN-фичей

Добавлены два уровня кэширования:

- `data/cache/cwt_scalograms` - кэш CWT-представлений, чтобы не пересчитывать wavelet transform для каждого CSV.
- `data/cache/cnn_features` - кэш признаков CNN-энкодера для режима frozen-CNN HPO.

Сохранение `.npy` сделано атомарным через временный файл и `os.replace`, поэтому при прерывании процесса меньше риск получить битый кэш.

Фактически в рабочем дереве уже есть крупный кэш:

- CWT-кэш: 34281 файла.
- CNN feature-cache: 64919 файлов.

Это показывает, что пайплайн не просто написан, а реально прогонялся на данных.

### 3.4. Предобучение CNN под RUL

Добавлен отдельный скрипт `src/prediction/pretrain_cnn_rul.py`.

Раньше CNN мог быть обучен как классификатор дефектов. Для RUL-задачи этого недостаточно: классификация отвечает на вопрос "какой класс дефекта?", а прогноз RUL требует понимать степень деградации. Поэтому был добавлен CNN-регрессор, который берет одиночную CWT-скалограмму и предсказывает нормированный RUL.

Результат сохраняется в:

```text
models/cnn/best_resnet18_rul.pth
```

В `src/prediction/config.py` добавлен fallback: если RUL-чекпоинт существует, используется он; если нет - используется старый классификационный `best_resnet18.pth`.

Также в `pretrain_cnn_rul.py` добавлены:

- график learning curves;
- scatter true-vs-predicted RUL;
- распределение residuals;
- CSV с метриками;
- SHAP-анализ CWT-скалограмм.

### 3.5. Двухфазное обучение

Новые скрипты обучаются в два этапа:

1. HPO-этап: CNN заморожен, Optuna подбирает параметры temporal-головы на заранее извлеченных CNN-фичах.
2. Final fit: модель обучается с лучшими параметрами либо в режиме `frozen`, либо в режиме `finetune`.

Это решает практическую проблему: полный fine-tuning CNN на каждом trial был бы слишком дорогим. Теперь подбор гиперпараметров быстрый, а тяжелое обучение запускается только для лучших конфигураций.

Для финального обучения добавлены:

- warmup-фаза, когда сначала обучается только temporal-голова;
- последующая разморозка CNN;
- discriminative learning rate: CNN обучается с меньшим learning rate, чем temporal-голова;
- ограничение batch size для экономии GPU-памяти;
- возможность сравнить `--final-fit-modes frozen finetune` в одном запуске.

### 3.6. Optuna, MLflow и визуализация

Во все три ветки встроена Optuna. Подбираются:

- `lr`;
- `hidden_size`;
- `dropout`;
- `batch_size`;
- `num_layers`;
- `weight_decay`;
- параметры loss;
- дополнительные параметры конкретных архитектур, например `kernel_size` у TCN, `patch_size` у PatchTST, `nhead` у Transformer-like моделей, `d_state` у Mamba.

MLflow логирует:

- параметры запуска;
- параметры модели;
- train/val/test-метрики;
- режим `frozen` или `finetune`;
- путь к CNN-чекпоинту;
- скорость инференса;
- артефакты чекпоинтов и графиков.

Генерируются:

- learning curves;
- RUL prediction plots;
- EMA-smoothed RUL prediction plots;
- residual plots;
- smoothed residual plots;
- Optuna optimization history;
- Optuna parameter importance;
- summary CSV;
- summary bar plot по test MSE.

### 3.7. Метрики

Помимо MSE и MAE добавлены:

- RMSE;
- R2;
- PHM score;
- скорость инференса в ms/sample;
- samples/sec.

Это позволяет сравнивать модели не только по точности, но и по применимости в реальном мониторинге.

## 4. Модельная ветка v3_rnn

### 4.1. Что требовал промпт

Промпт `PROMPT_agent_v3_rnn (1).md` требовал создать `train_rul_hybrid_v3_rnn.py`, оставить старые `lstm`, `gru`, `transformer` и добавить:

- `BiLSTMHead`;
- `LSTMAttentionHead`;
- `BiGRUHead`;
- `GRUAttentionHead`;
- `ImprovedTransformerHead`;
- локальную обертку `_LocalHybridRULNet`;
- регистрацию новых типов в `build_temporal_model`;
- отдельные experiment name, model dir, figure dir и suffix `_v3rnn`.

### 4.2. Что реализовано

Все пункты исходного задания реализованы. Ветка `v3_rnn` теперь поддерживает:

```text
lstm, gru, transformer,
bilstm, lstm_attn, bigru, gru_attn, transformer_improved
```

Новые архитектуры:

- `bilstm` - двунаправленный LSTM, который использует контекст слева и справа. Это уместно для offline-анализа, когда весь временной ряд уже доступен.
- `lstm_attn` - LSTM с temporal attention. Модель не обязана брать только последний hidden state, а может взвесить разные моменты деградации.
- `bigru` - двунаправленный GRU, более легкая альтернатива BiLSTM.
- `gru_attn` - GRU с attention для честного сравнения с LSTM+attention.
- `transformer_improved` - улучшенный Transformer с Pre-LN, learnable CLS-токеном и learnable positional encoding.

### 4.3. Смысл изменений

`v3_rnn` отвечает на исследовательский вопрос: достаточно ли усилить классические RNN attention-механизмом и bidirectional-контекстом, чтобы лучше описывать деградацию подшипника?

Эта ветка важна как переходная: она близка к предыдущему RNN-подходу, но дает более сильные варианты без полного изменения принципа модели.

### 4.4. Фактические артефакты

По `v3_rnn` сохранено 25 чекпоинтов в `models/preds_3_rnn`.

В `reports/figures/summary/train_rul_hybrid_v3_rnn` сохранен 141 файл графиков и CSV. Среди фактических balanced-прогонов есть, например:

- `transformer_improved_frozen`, `ws=1024`, `trials=30`, `epochs=10`: `test_mse=0.00923`, `test_rmse=0.24024`, `test_r2=0.10506`.
- `bilstm`, `ws=1024`, `trials=30`, `epochs=30`: `test_mse=0.01033`, `test_rmse=0.25547`.

Это можно использовать в отчете как подтверждение, что ветка была не только реализована, но и обучалась.

## 5. Модельная ветка v4_tcn

### 5.1. Что требовал промпт

Промпт `PROMPT_agent_v4_tcn.md` требовал создать `train_rul_hybrid_v4_tcn.py`, оставить старые `lstm`, `gru`, `transformer` и добавить:

- `TCNBlock`;
- `TCNHead`;
- `MultiScaleTCNHead`;
- `TCNAttentionHead`;
- `BiTCNHead`;
- `_LocalHybridRULNet`;
- регистрацию `tcn`, `tcn_ms`, `tcna`, `tcn_bi`;
- отдельные пути и suffix `_v4tcn`.

### 5.2. Что реализовано

Все основные пункты промпта реализованы. Ветка `v4_tcn` поддерживает:

```text
lstm, gru, transformer,
tcn, tcn_ms, tcna, tcn_bi
```

Новые архитектуры:

- `tcn` - классический causal TCN с residual-блоками, dilation и WeightNorm.
- `tcn_ms` - multi-scale TCN с параллельными ветками kernel size 3, 7 и 15.
- `tcna` - TCN с temporal attention поверх временной оси.
- `tcn_bi` - bidirectional/non-causal TCN, который использует весь временной контекст.

### 5.3. Смысл изменений

TCN-ветка проверяет альтернативу рекуррентным сетям. В отличие от LSTM/GRU, TCN:

- лучше параллелится;
- устойчивее на длинных последовательностях;
- использует dilated convolutions, поэтому видит широкий временной контекст без очень глубоких recurrent-цепочек;
- через multi-scale ветки может одновременно учитывать короткие всплески вибрации и медленный тренд деградации.

`tcn_bi` особенно полезен для offline-анализа, когда задача не требует строгой причинности и можно использовать весь фрагмент истории.

### 5.4. Дополнительные доработки

В Optuna-пространство для `tcn`, `tcna`, `tcn_bi` добавлен подбор `kernel_size` из вариантов 3, 5, 7. Это не было главным пунктом промпта, но делает сравнение TCN-честнее: модель может подобрать receptive field под данные.

Для `v4_tcn` отдельно настроены более осторожные параметры fine-tuning:

- `FINETUNE_WARMUP_EPOCHS = 3`;
- `FINETUNE_MAX_BATCH_SIZE = 2`;
- `FINETUNE_ENCODER_LR_MULT = 0.01`.

Это связано с тем, что TCN-варианты на окне 2048 тяжелее по памяти.

### 5.5. Фактические артефакты

По `v4_tcn` сохранено 15 чекпоинтов в `models/preds_4_tcn`.

В `reports/figures/summary/train_rul_hybrid_v4_tcn` сохранено 95 файлов графиков и CSV. Среди balanced-прогонов:

- `tcn_bi_finetune`, `ws=2048`, `trials=30`, `epochs=25`: `test_mse=0.01302`, `test_rmse=0.29660`.
- `tcn_bi_frozen`, `ws=2048`, `trials=30`, `epochs=25`: `test_mse=0.01307`, `test_rmse=0.26744`.

Отдельно видно, что сравнение frozen/finetune действительно проводится и сохраняется в summary CSV.

## 6. Модельная ветка v5_odd

### 6.1. Что требовал промпт

Промпт `PROMPT_agent_v5_odd.md` требовал создать `train_rul_hybrid_v5_odd.py` и добавить три современные архитектуры:

- `PatchTSTHead`;
- `ConformerHead`;
- `MambaHead`;
- graceful fallback для `mamba-ssm`;
- `_LocalHybridRULNet`;
- регистрацию `patchtst`, `conformer`, `mamba`;
- отдельные пути и suffix `_v5odd`.

Несмотря на название файла `v5_odd`, фактически реализованная ветка - это не NODE/LTC-направление, а SOTA temporal-направление: PatchTST, Conformer, Mamba. Это важно проговаривать в отчете, чтобы не было путаницы.

### 6.2. Что реализовано

Ветка `v5_odd` поддерживает:

```text
lstm, gru, transformer,
patchtst, conformer, mamba
```

Новые архитектуры:

- `patchtst` - разбивает временной ряд CNN-признаков на патчи, проецирует патчи в hidden space и обрабатывает Transformer encoder.
- `conformer` - сочетает feed-forward blocks, multi-head self-attention и depthwise convolution. Это гибрид локальных convolution-паттернов и глобального attention.
- `mamba` - selective state space model с линейной сложностью по времени. Если пакет `mamba-ssm` не установлен, модель не валит весь запуск, а пропускается с предупреждением.

### 6.3. Смысл изменений

`v5_odd` отвечает на вопрос: дают ли современные sequence-модели преимущество перед RNN и TCN на задаче RUL?

PatchTST полезен, потому что деградация часто проявляется локальными паттернами во времени: патчи позволяют модели работать не с отдельными шагами, а с короткими фрагментами динамики.

Conformer полезен тем, что сочетает два типа информации:

- локальные изменения сигнала через convolution;
- дальние зависимости через self-attention.

Mamba теоретически интересна для длинных последовательностей, потому что имеет линейную сложность и может моделировать долговременное состояние без квадратичной цены attention. При этом реализация корректно учитывает практическое ограничение: `mamba-ssm` требует отдельной установки и CUDA/Linux-окружения.

### 6.4. Дополнительные доработки

Для `v5_odd` в HPO добавлены параметры, специфичные для архитектур:

- `nhead` для PatchTST/Conformer;
- `patch_size` для PatchTST;
- `d_state` для Mamba.

Также добавлена проверка: если пользователь запросил `mamba`, но `mamba-ssm` недоступен, тип удаляется из списка запуска. Если после удаления не осталось моделей, скрипт завершится с понятной ошибкой.

### 6.5. Фактические артефакты

По `v5_odd` сохранено 9 чекпоинтов в `models/preds_5_odd`.

В `reports/figures/summary/train_rul_hybrid_v5_odd` сохранено 59 файлов графиков и CSV. Среди balanced-прогонов:

- `conformer_finetune`, `ws=2048`, `trials=30`, `epochs=25`: `test_mse=0.01297`, `test_rmse=0.27323`.
- `conformer_frozen`, `ws=2048`, `trials=30`, `epochs=25`: `test_mse=0.01327`, `test_rmse=0.25857`.

В fast-прогонах видно, что PatchTST без полноценного обучения может вести себя нестабильно, поэтому для отчета лучше делать акцент на balanced-результатах.

## 7. Автоматизация запусков

Добавлены shell-скрипты:

- `scripts/run_v3_rnn_balanced_freeze_then_finetune.sh`;
- `scripts/run_v4_tcn_balanced_freeze_then_finetune.sh`;
- `scripts/run_v5_odd_balanced_freeze_then_finetune.sh`;
- `scripts/run_all_hybrids_overnight.sh`.

Эти скрипты:

- сами выбирают Python runner: `uv run python`, `.venv/bin/python` или `python`;
- создают папки логов;
- проверяют наличие `models/cnn/best_resnet18_rul.pth`;
- при необходимости запускают `pretrain_cnn_rul.py`;
- запускают balanced-режим;
- обучают both modes: `frozen` и `finetune`;
- позволяют переопределять `WINDOW_SIZES`, `TEMPORAL_TYPES`, `N_TRIALS`, `EPOCHS`, `NUM_WORKERS`;
- сохраняют отдельные логи каждого запуска.

`run_all_hybrids_overnight.sh` объединяет все три ветки в один ночной pipeline. По умолчанию:

- V3 запускается на `ws=1024` для `lstm bilstm lstm_attn bigru gru_attn transformer_improved`;
- V4 запускается на `ws=2048` для `tcn tcn_ms tcna tcn_bi`;
- V5 запускается на `ws=2048` для `patchtst conformer mamba`.

Это удобно для практики: можно запустить длинную серию экспериментов один раз и утром получить чекпоинты, графики, CSV и MLflow-логи.

## 9. Как это можно сформулировать в отчете

В отчете можно сказать так:

> В ходе практики базовый гибридный CNN+temporal пайплайн был расширен до исследовательской платформы для сравнения трех семейств моделей прогнозирования RUL.
