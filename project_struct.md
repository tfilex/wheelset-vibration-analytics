# Структура проекта `wheelset-vibration-analytics`

Текущий проект представляет собой полноценный пайплайн для анализа и классификации вибросигналов подшипников. Ниже приведено детальное описание структуры директорий и назначения ключевых файлов.

## 📂 Данные (`data/`)

Папка содержит сырые наборы данных, на которых обучается и тестируется модель.

*   **`data/raw/CWRU/`** — Основной датасет (Case Western Reserve University). Разделен на 10 классов (подпапок), представляющих различные состояния подшипника:
    *   `0_Normal` — Нормальное состояние (здоровый подшипник).
    *   `1_IR_007` до `3_IR_021` — Дефекты внутреннего кольца (Inner Race) разного размера (от 0.007 до 0.021 дюйма).
    *   `4_Ball_007` до `6_Ball_021` — Дефекты тел качения (шариков).
    *   `7_OR_007` до `9_OR_021` — Дефекты внешнего кольца (Outer Race).
    *   *Внутри папок лежат исходные вибросигналы в формате `.mat`.*
*   **`data/raw/XJTU-SY/`** — Дополнительный датасет (представлен файлами `.csv` и документацией `Introduction_to_XJTU-SY_Bearing_Dataset.pdf`), который может быть использован для тестирования робастности моделей или трансферного обучения. Набор данных содержит эксперименты по ускоренному износу подшипников (run-to-failure) и структурирован по трем режимам работы:
    *   `35Hz12kN/` — Режим работы 1: частота вращения 35 Гц (2100 об/мин), радиальная нагрузка 12 кН. Включает 5 подшипников (`Bearing1_1` — `Bearing1_5`).
    *   `37.5Hz11kN/` — Режим работы 2: частота вращения 37.5 Гц (2250 об/мин), радиальная нагрузка 11 кН. Включает 5 подшипников (`Bearing2_1` — `Bearing2_5`).
    *   `40Hz10kN/` — Режим работы 3: частота вращения 40 Гц (2400 об/мин), радиальная нагрузка 10 кН. Включает 5 подшипников (`Bearing3_1` — `Bearing3_5`).
    *   *Внутри папок подшипников находятся `.csv` файлы, содержащие горизонтальные и вертикальные вибросигналы, записанные через определенные промежутки времени до момента полного разрушения подшипника.*

## 📂 Исходный код (`src/`)

Здесь находится вся логика работы с данными, нейросетями и визуализацией.

*   **`data_loader.py`** — Содержит класс `CWRUDataset` (наследуется от `torch.utils.data.Dataset`). Отвечает за чтение `.mat` файлов, извлечение 1D-сигнала, его нарезку на окна и потоковое преобразование в STFT-спектрограммы для подачи в нейросеть.
*   **`model.py`** — Содержит архитектуру нейронной сети `LightweightCNN`. Это легковесная сверточная сеть, которая принимает на вход 2D-тензоры спектрограмм и классифицирует их на 10 классов дефектов.
*   **`train.py`** — Скрипт обучения модели. Содержит цикл обучения (train/val split), интеграцию с системой трекинга **MLflow** для логирования метрик (Loss, Accuracy) и построения матрицы ошибок (Confusion Matrix) по итогам обучения.
*   **`preprocess.py`** — Дополнительный скрипт для предварительной обработки данных (если требуется оффлайн-препроцессинг).
*   **`visualization/plot_spectrograms.py`** — Мощный пайплайн для генерации графиков. Автоматически обходит все папки датасета CWRU и строит 5 типов диаграмм для каждого дефекта, а также сводные изображения для диссертации.

## 📂 Отчеты и визуализации (`reports/`)

Сгенерированные артефакты, готовые для вставки в диссертацию или презентацию.

*   **`reports/figures/individual/`** — Содержит подпапки для каждого из 10 классов (например, `0_Normal`, `1_IR_007`). В каждой подпапке лежат:
    *   `1_raw_signal.png` — Сырой вибросигнал во временной области.
    *   `2_stft.png` — STFT-спектрограмма.
    *   `3_cwt.png` — Скалограмма непрерывного вейвлет-преобразования (CWT).
    *   `4_envelope.png` — Спектр огибающей (Envelope Spectrum).
    *   `5_psd.png` — Спектральная плотность мощности (Метод Уэлча).
*   **`reports/figures/summary/`** — Сводные графики, где на одном изображении друг под другом сравниваются представители 4 ключевых классов (Норма, Внутреннее кольцо, Шарик, Внешнее кольцо). Отлично демонстрируют разницу между дефектами.

## ⚙️ Конфигурация и окружение

*   **`pyproject.toml`** — Главный конфигурационный файл проекта. Содержит метаданные проекта (название, описание) и список зависимостей (`torch`, `scipy`, `pywt`, `mlflow` и др.). Настроен для быстрой работы с менеджером пакетов `uv`.
*   **`uv.lock`** — Файл фиксации точных версий библиотек (lockfile). Гарантирует, что проект будет запускаться одинаково на любом компьютере.
*   **`.gitignore`** — Настроен на игнорирование системного мусора, виртуальных окружений (`.venv`), логов `mlruns/` и сгенерированных картинок, оставляя в репозитории только код и датасет.
*   **`setup_project.sh`** и **`requirements.txt`** — Legacy-файлы для альтернативной настройки окружения (до перехода на `uv`).
