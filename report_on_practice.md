# Отчёт по практике: Разработка гибридных глубоких архитектур для прогнозирования остаточного ресурса (RUL)

Данный документ содержит подробное описание изменений и улучшений, внесенных в архитектуру и пайплайн обучения моделей машинного обучения по сравнению с предыдущими версиями (v1/v2). Цель новых архитектур (семейства v3, v4, v5) — решение проблем переобучения, коллапса моделей и повышение интерпретируемости результатов предсказания остаточного ресурса (RUL) подшипников качения.

---

## 1. Концептуальные изменения и решение проблемы коллапса модели

В предыдущих версиях пайплайна (v2) наблюдалась серьезная проблема: при попытке совместного обучения (fine-tuning) извлекателя признаков (CNN) и временнóй модели (RNN) происходил **математический коллапс**. Модель скатывалась в предсказание константы (среднего значения), а метрика $R^2$ уходила в глубокий минус.

Для решения этой проблемы был внедрен ряд критических улучшений:

### 1.1. Двухэтапное гибридное обучение (Temporal Distance Regression)
Вместо использования весов CNN, обученных на задаче *классификации дефектов*, был внедрен отдельный этап **предобучения энкодера на задачу RUL** (`pretrain_cnn_rul.py`).
- Сверточная сеть (ResNet18) учится предсказывать степень деградации по одиночной CWT-скалограмме.
- Это заставляет фильтры сети реагировать на изменение амплитуды "дефектных" частот, а не просто констатировать факт наличия дефекта.

### 1.2. Кусочно-линейная деградация (Piecewise Linear RUL Target)
Введена функция ограничения целевой переменной (`rul_clip = 0.8`).
- **Проблема старого подхода:** При строгой линейной деградации (от 1.0 до 0.0 с первой секунды) сеть пыталась угадать время работы по фоновому шуму *здорового* подшипника, что приводило к жесткому переобучению (запоминанию конкретных подшипников).
- **Новый подход:** Первые 80% времени работы RUL считается константой (0.8). Сеть выучивает паттерн "здорового состояния". Падение RUL начинается только тогда, когда в вибрационном сигнале появляются реальные физические изменения. Это кардинально повысило обобщающую способность (generalization) модели на новых подшипниках.

### 1.3. Частичная разморозка и Discriminative Learning Rates (Gradual Unfreezing)
В основном цикле обучения (гибридном) реализована стратегия бережного дообучения (Fine-tuning):
1. **Frozen фаза:** CNN полностью заморожена. Обучается только "голова" (LSTM/TCN).
2. **Finetune фаза:** Размораживается только **последний блок** сверточной сети (`layer4`). При этом используется *discriminative learning rate* (скорость обучения для сверточных слоев в 10-100 раз ниже, чем для "головы"). Это предотвращает "катастрофическое забывание" (catastrophic forgetting) базовых физических признаков.

### 1.4. Внедрение объяснимого ИИ (Explainable AI - SHAP)
Для повышения научной ценности диссертации в пайплайн интегрирован `shap.GradientExplainer`. 
Теперь модель генерирует тепловые карты (Heatmaps) поверх оригинальных вейвлет-скалограмм. Это позволяет визуально доказать, что нейросеть принимает решения о скорой поломке на основе реальных физических частот (например, частот перекатывания шариков BPFI/BPFO), а не полагается на артефакты датасета.

## 2. Обзор новых архитектурных семейств (v3, v4, v5)

Новый пайплайн разделен на три ветки исследований, каждая из которых тестирует определенный класс моделей для анализа временных рядов (анализа последовательности 512-мерных векторов, извлеченных CNN).

### Модели семейства `v3_rnn` (Рекуррентные сети и Внимание)
Классический подход к анализу временных последовательностей. Хорошо улавливают нелинейные тренды деградации, но подвержены проблеме затухания градиентов на длинных окнах.
- **`lstm` / `gru`:** Базовые реализации. GRU показывает себя более устойчивым к переобучению из-за меньшего числа параметров.
- **`bilstm`:** Двунаправленная сеть. Полезна для ретроспективного анализа (offline-мониторинг), когда доступен весь временной ряд.
- **`lstm_attn` / `gru_attn`:** Рекуррентные сети, усиленные механизмом внимания (Attention). Позволяют сети "фокусироваться" на тех временных шагах (окнах), где произошел резкий скачок деградации (например, откол частицы металла).
- **`transformer_improved`:** Использование механизма Multi-Head Self-Attention. Эффективно для поиска сложных долгосрочных зависимостей без ограничений, присущих шаговому проходу RNN.

### Модели семейства `v4_tcn` (Временные сверточные сети)
Использование одномерных сверток с расширением (Dilated 1D Convolutions). Это более современная альтернатива RNN, решающая проблему исчезающего градиента и работающая значительно быстрее за счет параллельных вычислений.
- **`tcn`:** Классический Causal TCN (модель не заглядывает в будущее, строгая причинность).
- **`tcn_ms` (Multi-scale TCN):** Параллельные сверточные ветки с разными размерами ядра (например, 3, 7, 15). Позволяют одновременно анализировать как быстрые высокочастотные флуктуации (микротрещины), так и медленные макро-тренды износа.
- **`tcna`:** TCN, дополненный блоком временного внимания, чтобы взвешивать важность извлеченных сверткой паттернов.
- **`tcn_bi`:** Непричинный (non-causal) TCN для offline-анализа.

### Модели семейства `v5_odd` (Непрерывные динамические модели)
Экспериментальное направление, использующее дифференциальные уравнения для моделирования скрытого состояния системы. Поскольку износ подшипника — это непрерывный физический процесс, такие модели теоретически наиболее адекватны физике явления.
- **`node` (Neural Ordinary Differential Equations):** Скрытое состояние обновляется не дискретными шагами (как в RNN), а с помощью решателя ОДУ (ODE Solver). Позволяет работать с нерегулярно поступающими данными с датчиков.
- **`ssm` (State-Space Models):** Современные модели пространства состояний (вдохновленные Mamba/S4), эффективно моделирующие долгосрочные зависимости с математическими гарантиями стабильности.
- **`ltc` (Liquid Time-Constant Networks):** Сети, чьи "постоянные времени" меняются динамически в зависимости от входа. Идеально подходят для систем, где подшипник может резко ускорить деградацию после определенного порога износа.

## 3. Оптимизация гиперпараметров и автоматизация
- Во все три скрипта (`v3_rnn`, `v4_tcn`, `v5_odd`) внедрен **Optuna**. Гиперпараметры (learning rate, hidden_size, dropout и др.) подбираются автоматически для каждой архитектуры.
- Логирование полностью переведено на **MLflow**, что позволяет автоматически отслеживать Loss, метрики ($R^2$, MAE, RMSE) и сохранять артефакты (графики сглаженных предсказаний, гистограммы остатков).
- Во всех модулях визуализации применен метод `fig.tight_layout()`, что обеспечило академическое качество графиков для вставки в финальный текст диссертации.
